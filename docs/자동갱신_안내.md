# 매칭 데이터 자동 갱신 안내

## 하는 일
- 하루 두 번(한국 시간 05:30, 17:30) 퍼플 라운지에서 새 "서버 매칭" 글이 있는지 확인합니다.
- 새 글이 있으면 혼돈의 어비스 표(서부/동부 서버)를 읽어서 `matching.json`을 바꿉니다.
- 앱은 시작할 때와 6시간마다 이 파일을 받아서 서버별 **매칭 그룹 · 그룹 · 서부/동부**를 표시합니다.
- 표를 제대로 읽지 못하거나 서버 42개가 맞지 않으면 **파일을 바꾸지 않고** 작업을 실패로 표시합니다(GitHub가 메일로 알려 줍니다). 앱은 마지막 정상 데이터를 계속 씁니다.

## 지켜서 만든 규칙
`lounge.plaync.com/robots.txt` 가 허용한 범위만 사용합니다: `sitemap.xml` 과 `/feed/<글번호>` 글 페이지.
`/tag/`, `/search/`, `/api/` 는 접근이 막혀 있어서 쓰지 않습니다. 요청은 1초에 한 번 이하이고, 보통 하루에 수십 건 이내입니다.

## 처음 한 번만 설치하기
1. GitHub의 `pinlog/aion2bosscheck` 저장소를 엽니다.
2. 이 폴더의 파일을 **저장소 맨 위(main)** 에 올립니다. 폴더 구조를 그대로 유지해야 합니다.
   - `matching.json`, `README.md`
   - `tools/` 폴더 전체
   - `.github/workflows/update-matching.yml`
   - 올리는 방법: 저장소 화면 **Add file → Upload files** 에 폴더째 끌어다 놓고 **Commit changes**.
     `.github` 폴더가 업로드되지 않으면 **Add file → Create new file** 에서 파일 이름 칸에 `.github/workflows/update-matching.yml` 을 입력하고 내용을 붙여넣으세요.
3. 저장소 **Settings → Actions → General → Workflow permissions** 에서 **Read and write permissions** 를 선택하고 Save 합니다.
4. 저장소 **Actions** 탭 → `update-matching` → **Run workflow** 를 눌러 한 번 실행해 봅니다. 초록색 체크가 나오면 정상입니다.
   (처음에는 `새 매칭 글이 없습니다`로 끝나는 것이 정상입니다. 올린 `matching.json` 이 이미 최신 글 `87252` 기준입니다.)
5. 앱 시험: 내 PC에만 1.0.7을 설치한 뒤 서버 설정창의 `매칭 데이터 확인` 버튼을 누릅니다. `챕터1 두 번째 이야기 1차 적용 완료` 가 나오면 GitHub 와 연결된 것입니다.

## 새 매칭이 올라왔을 때
- 보통은 아무것도 하지 않아도 됩니다. 하루 두 번 확인합니다.
- 자동으로 잡히지 않으면(사이트맵에 늦게 올라올 수 있습니다) **Actions → update-matching → Run workflow** 에서 `글 번호`에 라운지 글 주소의 숫자를 넣고 실행합니다.
  예: `https://lounge.plaync.com/feed/84791` 이면 `84791`.
- 앱에서는 서버 설정창의 **매칭 데이터 확인** 버튼으로 바로 받아 볼 수 있습니다.

## 비상 수단: 변환 도구
`tools/converter.html` 을 더블클릭해서 열고, 공지의 어비스 표를 복사해 붙여넣으면 `matching.json` 으로 바꿔 줍니다. 그 파일을 저장소에 올리면 됩니다.

## 내 PC에서 먼저 시험하기
받은 `matching.json` 을 `%APPDATA%\aion2-bosscheck\` 폴더(앱의 창 위치 파일이 있는 곳)에 넣고 앱을 다시 실행합니다.
이 파일이 GitHub 데이터보다 우선합니다. 확인이 끝나면 지우세요.

## 글 형식
- 두 번째 이야기 1차부터는 `A그룹 / B그룹 / C그룹` 별로 서부·동부 서버만 적혀 있고 매칭 그룹 번호가 없습니다. 도구는 알려진 순서(A는 1·4·7…, B는 2·5·8…, C는 3·6·9…, 각 목록 위에서부터)로 번호를 붙입니다.
- 이전 형식(번호가 적힌 표)도 계속 읽습니다.

## 알려진 한계
- 게임사가 표 형식을 또 바꾸면(예: 그룹당 줄 수가 달라지는 경우) 읽기에 실패합니다. 실제 글을 보고 규칙을 고쳐야 합니다.
- 새 글 찾기는 사이트맵 기준입니다. 사이트맵에 늦게 올라오는 글은 글 번호를 직접 입력하세요.
- 사이트가 자동 접근을 막는 정책으로 바꾸면 중단하는 것이 맞습니다. **Actions → update-matching → ⋯ → Disable workflow**.
